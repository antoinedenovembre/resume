# Development Guide

This document contains detailed information for developers who want to work on or understand the technical aspects of this LaTeX resume project.

## Local Development

### Prerequisites

- LaTeX distribution (TeX Live, MiKTeX, or MacTeX)
- `latexmk` command-line tool

### Building Locally

```bash
# Generate LaTeX content files from the YAML data (optional; use if you want to generate content without building PDFs)
make generate

# Build all 16 PDFs: 4 styles × with/without photo × EN/FR (recommended)
make all

# Build all English versions (every style, with and without photo)
make en

# Build all French versions (every style, with and without photo)
make fr

# Build every variant of one style
make default
make tech
make minimal
make sidebar

# Build a specific variant: <style>_<with|no>_image_<en|fr>
make default_with_image_en
make tech_no_image_fr

# Clean auxiliary files (keeps PDFs and generated content)
make clean

# Clean all generated files including PDFs and generated LaTeX content
make clean-all

# List build logs, or show the end of one (named <style>_resume_<variant>)
make logs
make tail-sidebar_resume_with_image_fr
```

PDFs are written next to their root file: `build/<style>/resume_<variant>.pdf`.

### Development Notes
- All source files are organized in the `src/` directory
- Built PDFs are generated in `build/<style>/`
- Resume content is stored in `data/resume.yml` (single file for all languages)
- LaTeX content files in `src/content/` are **generated** from the YAML — do not edit them directly
- The build process automatically generates content files when `data/resume.yml` changes
- Modular architecture allows easy customization of individual components
- **Multi-language support**: English and French versions with shared configuration and styling

## Automated Compilation

Every push to the `main` branch automatically:

1. Compiles all 16 resume versions (4 styles × English/French × with/without photo), one CI job each
2. Creates a "latest" release with one zip per style (`resume-default.zip`, `resume-tech.zip`, `resume-minimal.zip`, `resume-sidebar.zip`) plus the default-style PDFs used by the README and site links
3. Regenerates the previews in `assets/previews/` (one per style, plus the FR/EN previews used by the site)
4. Stores artifacts for 30 days

## Modular Architecture

- **Content** (`data/resume.yml` → `src/content/`): the generator emits semantic macros, never layout: `resumeentry` (with an optional short name), `resumehighlights`, `resumeskillssection`, `resumeskills` and `\resumeskill`.
- **Shared configuration** (`src/config/`): packages, commands and the base rendering of those macros in `style.tex`, which is the default style.
- **Styles** (`src/styles/<style>/`): `style.tex` redefines the macros, the two headers place the name, contacts and photo.
- **Root files** (`build/<style>/`): load the shared config, then the style, then the header and the content. `\ResumeRoot` holds the path back to the repository root.

### Styles

| Style | Look | Notes |
|-------|------|-------|
| `default` | Original layout, icons, blue links | `style.tex` is empty: the base rendering is used as is |
| `tech` | Times font, ruled uppercase sections, date column on the left | Uses an entry's `short_name` (e.g. `UQAC`) when the heading would not fit on one line |
| `minimal` | Source Sans, gray letter-spaced titles, no rules or icons | Round photo on the right of the name |
| `sidebar` | Roboto, colored left column with photo, contacts and skills | Skills are collected while the content is read and drawn in the sidebar at shipout, so the resume must stay on one page |

### Adding a style

1. Create `src/styles/<name>/` with `style.tex`, `header_with_image.tex` and `header_no_image.tex` (copy an existing style as a starting point)
2. Create the 4 root files in `build/<name>/` (copy another style's and change the style folder name)
3. Add `<name>` to `STYLES` in the `Makefile`, to the `style` matrix in `compile.yml`, and to the style loops in `release.yml` and `preview.yml`
4. Run `make <name>` to check the 4 PDFs

### Multi-language Support

- **Shared Configuration**: All languages use the same packages, styles, and commands
- **Single Data File**: Both EN and FR content live in `data/resume.yml` under `en:` and `fr:` keys
- **Generated Content**: `scripts/generate_tex.py` converts the YAML into language-specific LaTeX files
- **Consistent Build System**: Simple `make en` and `make fr` commands to build all versions for each language

## Versioning

- **Latest Release**: Always contains the most recent compiled PDFs
- **Dated Archives**: Each time `latest` is replaced, the previous one is kept as a dated release tagged `dd.mm.yyyy` (e.g. `08.10.2026`, with `-2`, `-3`… if a day has several)

## LaTeX Packages Used

### Core Packages
- `geometry` - Page layout and margins configuration
- `titlesec` - Section title customization
- `tabularx` & `array` - Advanced table formatting
- `xcolor` - Color definitions and primary color scheme
- `enumitem` - List customization and styling
- `fontawesome5` - Professional icons integration
- `hyperref` & `bookmark` - PDF metadata, links, and navigation

### Layout & Formatting
- `amsmath` - Mathematical expressions support
- `eso-pic` - Floating text positioning
- `calc` - Length calculations
- `lastpage` - Total page count reference
- `changepage` - Adjustable width environments
- `paracol` - Multi-column layout support
- `needspace` - Intelligent page break management

### Style-specific Packages
- `newtxtext` (tech), `sourcesanspro` and `microtype` (minimal), `roboto` (sidebar), `xstring` (minimal and sidebar)

### Conditional Packages (Photo Version Only)
- `graphicx` - Image inclusion for profile photo
- `tikz` - Graphics and diagrams creation

### Engine Compatibility
- `iftex` - LaTeX engine detection
- `ifthen` - Conditional statements
- PDF/A compatibility packages for ATS parsing

## Advanced Features

### Conditional Compilation
The project uses intelligent conditional compilation:
- Photo-related packages (`graphicx`, `tikz`) are only loaded for the photo versions
- Keeps the no-image version lightweight and faster to compile
- Maintains ATS (Applicant Tracking System) compatibility

### PDF Optimization
- Machine-readable PDF generation for ATS parsing
- Unicode character mapping for text extraction
- Proper PDF metadata and navigation bookmarks
- Color-coded links with professional styling

### Build System
- Automated cleanup of auxiliary LaTeX files
- Parallel compilation support via Makefile
- Consistent output in `build/<style>/`
- Development-friendly with modular source organization
